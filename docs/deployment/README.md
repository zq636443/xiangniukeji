# 部署说明

第一版建议部署：

- 两个支付宝小程序发布到支付宝小程序平台。
- 总部后台静态资源由 Nginx 托管。
- 后端服务使用 Docker 部署。
- MySQL 使用云数据库 RDS。
- Redis 使用云 Redis。
- 对象存储使用 OSS/COS。
- 支付回调、合同回调、核销回调必须使用 HTTPS 域名。

上线前必须配置：

- MySQL RDS 自动备份，至少保留 7 天，关键上线节点手动创建快照。
- Redis 开启持久化或使用云厂商备份能力。
- 后端健康检查、错误率、接口延迟、扣款失败数、支付回调失败数、对账差异数告警。
- 支付宝账单文件下载、解析和平台对账批次建议由定时任务触发，生产环境需配置支付宝证书、密钥和账单日期调度。
- 导出文件应落到对象存储私有桶，后台只保存带权限控制的下载地址。

## 管理后台浏览器兼容与缓存

- 管理后台生产构建同时生成现代模块脚本和旧版 Safari 使用的 `nomodule` 兼容脚本，部署时必须完整上传 `admin-web/dist/`，不能只替换 `index.html` 或主脚本。
- `index.html` 必须使用 `no-cache, no-store`，`/assets/` 下带哈希资源使用长期缓存；不要让入口文件长期缓存，否则旧设备可能继续引用已经被删除的历史脚本并出现白屏。
- 发布新版本后应重新构建管理后台镜像，不要在旧容器中手工覆盖少量静态文件。
- 当前兼容目标为 Safari 11 及以上、iOS 11 及以上。更老系统若仍无法建立 HTTPS 连接，需要检查证书链、TLS 协议和反向代理是否保留 TLS 1.2 兼容能力。
- 手机端使用抽屉导航，后台表格在窄屏下通过局部横向滚动查看，页面本身不应产生横向溢出。
