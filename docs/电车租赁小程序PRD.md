# 电车租赁小程序 PRD

## 1. 项目概述

### 1.1 产品定位

本项目是面向电车租赁行业的多商户、多门店资产交易、租赁与核销平台。平台总部在后台创建合作商户与门店，并为每个门店生成专属二维码。用户可通过抖音、美团等线上渠道购买团购套餐后到合作门店扫码进入用户版小程序核销，也可直接到店扫码进入用户版小程序选择商品完成线下直租。商户和门店员工通过商户版小程序处理核销协助、取还车、资产更换、结束订单和收益查看。后续平台支持资产售卖，用户可一次性买断资产，也可分期付款购买资产。

平台核心价值：

- 统一管理合作商户、门店、商品、套餐、车辆/电池资产。
- 支持抖音、美团团购券码核销。
- 支持线下直租订单，由平台统一收款。
- 支持资产售卖，一次性买断或分期付款。
- 支持商品链接配置签单费承担方，可由商户承担或用户承担。
- 支持芝麻信用免押。
- 支持跨门店归还。
- 支持资产绑定、资产更换和租赁履约记录沉淀。

### 1.2 平台形态

- 用户端：第一版本为支付宝用户版小程序。
- 商户端：第一版本为支付宝商户版小程序。
- 管理端：总部后台 Web。

### 1.3 适配平台

第一版本包含两个支付宝小程序：支付宝用户版小程序、支付宝商户版小程序。暂不兼容微信小程序。微信小程序、微信支付和微信自动扣款能力作为后续版本扩展。

需要适配的平台能力：

- 支付宝登录。
- 支付宝支付。
- 芝麻信用免押授权。
- 小程序扫码、输入券码。
- 抖音生活服务团购核销 API。
- 美团团购券核销 API。

## 2. 业务目标

### 2.1 产品目标

- 帮助总部统一管理多城市、多商户、多门店租赁业务。
- 帮助合作门店快速承接抖音、美团等线上团购用户。
- 打通线上团购核销与线下租车履约流程。
- 支持线下自然到店用户在小程序内完成下单和支付。
- 沉淀门店订单、签单费、资产使用、还车、结算等数据。

### 2.2 业务指标

- 门店二维码扫码次数。
- 商品详情访问量。
- 线上券码核销成功率。
- 线下直租下单转化率。
- 签单费收入。
- 租金收入。
- 免押授权成功率。
- 跨店归还订单占比。
- 异常订单数量。

## 4. 核心业务规则

### 4.1 门店二维码规则

总部为每个门店生成一个独立二维码。二维码需要携带门店身份信息，用户扫码后进入该门店的小程序页面。

二维码参数建议：

| 字段 | 说明 |
| --- | --- |
| merchant_id | 商户 ID |
| store_id | 门店 ID |
| scene | 场景码 |
| channel | 来源渠道，默认 store_qr |
| operator_id | 可选，员工或业务员 ID |

用户扫码进入后，系统自动识别当前门店，并展示该门店可售卖或可核销的商品与套餐。

### 4.2 商品链接规则

后台配置商品或套餐链接时，需要支持以下配置：

- 商品基础价格。
- 交易模式：租赁、售卖、租售两用。
- 售卖方式：一次性买断、分期付款。
- 售卖价格。
- 售卖分期期数和每期金额。
- 租赁周期：日租、周租、月租、自定义周期。
- 签单费金额。
- 签单费承担方：商户承担 / 用户承担。
- 是否支持线上团购核销。
- 是否支持线下直租。
- 是否需要芝麻信用免押。
- 是否需要绑定资产。
- 是否支持跨店归还。
- 适用门店范围。
- 适用平台：支付宝、抖音、美团、线下；微信后续版本扩展。

商品链接采用“全局 SKU + 门店 SKU”的配置方式：

- 全局 SKU：总部维护商品基础信息、图片、分类、默认价格、默认办单费、默认分配规则。
- 门店 SKU：门店维度的实际售卖链接，可覆盖价格、办单费、签单费承担方、租金分配比例、上下架状态、适用渠道。
- 同一个 SKU 在不同门店可以有不同商品链接、不同租金、不同办单费和不同分配比例。
- 每个门店可配置自己展示的商品链接，不配置则不在该门店展示。
- 支持总部批量选择门店，将一个或多个 SKU 批量上架到多个门店。
- 批量上架时可选择使用默认分润模板，或批量覆盖门店 SKU 配置。

### 4.3 费用规则

| 订单来源 | 用户支付内容 | 平台记录收入 | 说明 |
| --- | --- | --- | --- |
| 抖音团购核销 | 团购款已在抖音支付，小程序内需支付签单费 | 签单费 | 签单费承担方可配置为商户或用户 |
| 美团团购核销 | 团购款已在美团支付，小程序内需支付签单费 | 签单费 | 签单费承担方可配置为商户或用户 |
| 线下扫码直租 | 商品租金 + 签单费 | 商品租金 + 签单费 | 平台统一收款 |
| 后付商品 | 按配置生成应收金额 | 应收租金 + 签单费 | 可用于后付或特殊套餐 |
| 资产一次性买断 | 售卖价格 + 可选服务费 | 售卖收入 | 支付完成后进入资产交付/过户流程 |
| 资产分期付款 | 首期款 + 后续分期账单 | 售卖收入分期确认 | 先付后用/先付后交付规则可配置 |

签单费承担逻辑：

- 用户承担：用户在小程序支付签单费。
- 商户承担：用户无需支付签单费，系统在商户结算中扣除签单费。

### 4.4 资产售卖规则

平台除租赁模式外，需要支持资产售卖模式。

售卖模式：

- 一次性买断：用户一次性支付资产售卖价格，支付完成后进入资产交付和权属变更流程。
- 分期付款：用户支付首期款，并签约自动扣款协议，后续按账单周期自动扣款。

售卖商品配置：

- 是否允许售卖。
- 售卖资产类型：整车、车架、电池、车架 + 电池。
- 售卖价格。
- 是否支持分期。
- 支持后台自定义期数。
- 首付金额或首期金额。
- 每期账单金额。
- 账单日规则。
- 是否需要电子合同。
- 是否需要自动扣款签约。
- 是否需要资产交付确认。
- 是否立即过户或尾款结清后过户。

售卖流程：

1. 用户扫码进入门店页。
2. 用户选择可售卖商品。
3. 用户选择一次性买断或分期付款。
4. 用户完成实名、合同签署和必要协议确认。
5. 一次性买断场景，用户支付全款。
6. 分期付款场景，用户支付首期款并完成自动扣款签约。
7. 门店完成资产交付，记录车架号、电池号或两者。
8. 系统根据配置处理资产权属：立即过户或尾款结清后过户。
9. 订单进入已完成或分期履约中。

资产权属规则：

- 租赁订单中，资产所有权仍属于平台或出资方。
- 一次性买断支付完成并交付后，可将资产状态更新为已售出。
- 分期付款未结清前，资产可配置为保留所有权，用户仅拥有使用权。
- 分期付款全部结清后，系统触发资产权属变更。
- 资产出售后，对应资产不再进入租赁库存。

售卖分润规则：

- 售卖订单可配置门店服务费或销售佣金。
- 出资方资产售卖后，售卖净收益归属对应出资方，扣除运营手续费、维保费、销售佣金、扣罚等费用。
- 售卖订单同样需要保存收益规则快照。

### 4.5 收益分配规则

平台资产铺设到合作门店后，门店收益主要由两部分组成：

- 办单费收益：用户完成有效租赁订单后，门店获得对应资产或商品配置的办单费。
- 租金分成收益：平台按订单租金和 SKU/门店配置的分配比例向门店分配租金收入。

分配规则需要灵活配置：

- 不同 SKU 可设置不同租金分配比例。
- 同一个 SKU 在不同门店可设置不同租金分配比例。
- 同一门店下不同 SKU 可设置不同办单费和分配比例。
- 分配比例可支持平台比例、门店比例，也可扩展业务员/代理比例。
- 分配比例需要支持出资方收益比例，用于不同出资方查看和结算名下资产收益。
- 可配置分配规则生效时间和失效时间。
- 修改分配规则后，不影响已生成订单，已生成订单按下单时的规则快照结算。

分润优先级：

1. 门店 SKU 独立分润规则。
2. 门店级默认分润规则。
3. SKU 默认分润规则。
4. 平台默认分润规则。

分润计算示例：

| 项目 | 说明 |
| --- | --- |
| 订单租金 | 用户支付或应收的租金金额 |
| 办单费 | 门店固定收益，可按单、按期或按套餐配置 |
| 门店租金分成 | 订单租金 * 门店分成比例 |
| 出资方收益 | 订单租金 * 出资方分成比例，或按资产收益规则计算 |
| 平台租金留存 | 订单租金 * 平台分成比例 |
| 门店应结算金额 | 办单费 + 门店租金分成 - 商户承担费用 - 扣罚金额 |

### 4.6 出资方与资产收益归属规则

平台资产可能来自不同出资方，资产需要挂靠到对应出资方名下，便于出资方查看资产状态和收益。

资产归属规则：

- 每个车辆/车架资产必须支持绑定出资方。
- 每个电池资产必须支持绑定出资方。
- 同一订单可能绑定车架和电池，车架与电池可以属于同一个出资方，也可以属于不同出资方。
- 资产调拨到不同门店后，资产所有权不变，资产所在门店变化。
- 资产归属发生变更时，需要记录变更历史。
- 订单创建或资产绑定时，需要保存出资方归属快照，历史订单收益按快照结算。

出资方收益规则：

- 可按资产维度配置收益比例。
- 可按出资方维度配置默认收益比例。
- 可按 SKU 或门店 SKU 维度配置出资方收益比例。
- 每个出资方可配置独立运营手续费比例。
- 运营手续费从出资方毛收益中按比例扣除。
- 不同资产类型可配置不同维保费用，维保费支持固定金额。
- 出资方最终结算金额 = 出资方毛收益 - 运营手续费 - 维保费用 - 其他扣罚 + 报废残值。
- 当订单同时绑定车架和电池，且两者出资方不同，需要支持按资产类型拆分收益。
- 出资方收益可参与每期账单、续租账单和逾期补缴账单计算。
- 出资方运营手续费规则需要在订单或账单生成时保存快照，避免后续比例调整影响历史收益。
- 维保费规则需要按资产类型保存快照，避免后续调整影响历史收益。
- 资产报废后产生的残值收益归属对应资产出资方。

出资方可查看：

- 名下资产总数。
- 名下资产当前所在门店。
- 名下资产状态：空闲、租赁中、维修中、停用、遗失。
- 名下资产关联订单。
- 名下资产产生的租金收益。
- 名下资产扣除的运营手续费和维保费用。
- 名下资产报废残值收益。
- 名下资产待结算、已结算金额。
- 名下资产调拨、维修、更换、归还记录。

### 4.7 核销规则

线上购买用户到店后，可通过以下方式核销：

- 手动输入券码。
- 扫描券码。

核销流程：

1. 用户扫码进入门店页。
2. 用户选择抖音或美团核销入口。
3. 用户输入或扫描券码。
4. 系统调用对应平台接口验券。
5. 返回券码状态、商品信息、有效期、可核销门店等信息。
6. 系统匹配本平台商品/套餐。
7. 根据商品配置判断是否需要支付签单费。
8. 用户完成签单费支付，或系统记录商户承担。
9. 系统调用第三方平台核销接口。
10. 核销成功后创建本平台租赁订单。
11. 用户进入取车和免押流程。

核销状态：

| 状态 | 说明 |
| --- | --- |
| 待验券 | 用户已录入券码，尚未完成验券 |
| 验券成功 | 券码有效，可继续核销 |
| 验券失败 | 券码无效、已过期、已使用或门店不适用 |
| 待支付签单费 | 需要用户支付签单费 |
| 签单费已支付 | 用户完成签单费支付 |
| 待第三方核销 | 已满足核销条件，准备调用第三方核销 |
| 已核销 | 第三方平台核销成功 |
| 核销失败 | 第三方平台核销失败 |
| 已生成租赁订单 | 本平台订单创建成功 |

### 4.8 资产绑定规则

租赁订单需要支持绑定以下资产类型：

- 只绑定车架号。
- 只绑定电池号。
- 同时绑定车架号和电池号。

适用场景：

- 只租车架：订单只绑定车辆/车架资产。
- 只租电池：订单只绑定电池资产。
- 车和电池一起租：订单同时绑定车架与电池资产。

资产需要支持更换：

- 更换车辆。
- 更换电池。
- 同时更换车辆和电池。

更换时需要记录：

- 原资产编号。
- 新资产编号。
- 更换原因。
- 操作门店。
- 操作人。
- 更换时间。
- 用户确认记录。
- 是否产生额外费用。

### 4.9 免押规则

平台需要接入芝麻信用免押能力。

免押流程：

1. 用户在订单页点击免押授权。
2. 跳转支付宝/芝麻信用授权。
3. 授权成功后返回小程序。
4. 系统记录免押状态。
5. 若免押成功，用户无需支付押金。
6. 若免押失败，根据商品规则提示支付押金或无法下单。

免押信息需要记录：

- 用户 ID。
- 订单 ID。
- 授权平台。
- 芝麻信用授权单号。
- 免押金额。
- 授权状态。
- 授权时间。
- 解约时间。

### 4.10 跨门店归还规则

商品或套餐可配置是否支持跨门店归还。

跨店归还规则：

- 支持跨店归还时，用户可在可归还门店列表中选择还车门店。
- 不支持跨店归还时，只能归还到取车门店。
- 跨店归还可配置额外服务费。
- 还车门店需要具备对应资产接收权限。

订单需要记录：

- 取车门店。
- 计划还车门店。
- 实际还车门店。
- 是否跨店归还。
- 跨店费用。

### 4.11 还车与自动续租规则

订单到达约定还车时间后，需要根据资产归还情况自动判断订单状态。

短租还车规则：

- 用户在约定时间内归还车辆/电池，门店完成资产归还确认后，订单结束。
- 用户到店还车时，门店员工需要核对车架号、电池号或两者，并在后台/商户权限端确认归还资产。
- 若订单绑定了车架和电池，则需要同时完成车辆与电池归还确认。
- 若订单只绑定车架或只绑定电池，则只需归还对应资产。
- 归还完成后，系统释放资产状态，并将订单状态更新为已完成。

逾期自动续租规则：

- 用户未在订单规定时间内完成还车，系统自动进入续租流程。
- 自动续租按商品配置的续租周期和续租价格计费。
- 续租周期可按商品或套餐自定义。
- 所有租期的订单逾期后都需要生成逾期/续租账单，并进入自动扣费流程。
- 系统根据订单的账单周期、授权方式和扣款产品规则选择扣费通道。
- 7 天及以上账单周期可使用支付宝周期/商家扣款协议，由平台服务端主动发起扣款。
- 小于 7 天的逾期费用不使用支付宝周期/商家扣款，需通过芝麻免押/资金授权扣费、用户主动补缴或后台人工处理兜底。
- 自动扣款成功后，订单预计还车时间顺延一个续租周期。
- 自动扣款失败时，订单进入待补缴或逾期异常状态，并触发提醒。

自动续租状态：

| 状态 | 说明 |
| --- | --- |
| 待还车 | 已到达或即将到达约定还车时间 |
| 已逾期 | 超过约定还车时间，尚未完成归还 |
| 续租扣款中 | 系统正在发起自动续租扣款 |
| 续租成功 | 扣款成功，还车时间顺延 |
| 续租失败 | 扣款失败，等待用户补缴或人工处理 |
| 逾期异常 | 多次扣款失败或超出风控规则 |

### 4.12 分期租赁与账单规则

平台需要支持后台自定义租期和自定义期数。整体业务采用先付后用逻辑。

分期规则：

- 后台可配置商品支持的任意期数。
- 每期可按自然月、固定天数或自定义账单周期生成账单。
- 支持配置每期天数、总期数、首期金额、每期金额、账单日和到期规则。
- 用户下单时需要完成首期支付。
- 用户需要完成支付宝周期扣款或商家扣款签约，用于后续账单自动扣款。
- 每月账单日由订单起租日、后台配置或合同约定生成。
- 每期账单扣款成功后，用户获得下一周期使用权。
- 扣款失败时，订单进入待补缴状态，并按规则限制续租、还车、换车或新下单。
- 每月账单扣款失败后，系统需要进入逾期订单汇总，便于运营统一催缴和财务统计。

账单生成规则：

| 字段 | 说明 |
| --- | --- |
| total_periods | 总期数，后台自定义 |
| current_period | 当前期数 |
| bill_day | 每期账单日 |
| bill_amount | 每期应收金额 |
| due_time | 应支付截止时间 |
| bill_status | 待扣款、扣款中、已支付、扣款失败、已关闭 |

扣款规则：

- 首期：用户主动支付。
- 后续期：由平台服务端定时任务根据支付宝扣款协议号主动调用支付宝扣款接口，支付宝不会自动按账单日替商户发起扣款。
- 支付宝周期/商家扣款最短扣款周期为 7 天；短于 7 天的账单周期不进入支付宝周期/商家扣款范围。
- 所有逾期订单都必须进入自动扣费策略：优先按可用协议扣款，协议不可用时转入免押/资金授权扣费，仍失败则进入主动补缴和人工催缴。
- 支持账单日前提醒。
- 支持扣款失败后重试。
- 支持人工补缴。
- 支持扣款失败后生成逾期记录。
- 支持按月汇总逾期订单、逾期金额、失败次数和催缴状态。
- 支持提前还车时计算已用期数、未用期数和应退/应补金额。

### 4.13 电子签约与实名规则

长租、分期、免押、高价值资产租赁或资产售卖场景需要在取车/交付前完成电子签约。

签约前置要求：

- 用户上传身份证正面。
- 用户上传身份证反面。
- 系统识别身份证信息。
- 用户确认实名信息。
- 必要时进行人脸核身。
- 生成电子租赁合同或资产买卖合同。
- 用户完成电子签署。
- 签署完成后才允许进入取车或资产交付流程。

电子合同需要包含：

- 用户身份信息。
- 商户/平台主体信息。
- 租赁商品类型或售卖资产类型。
- 租赁周期或售卖交付规则。
- 账单期数。
- 每期金额。
- 自动扣款授权说明。
- 押金或免押规则。
- 逾期自动续租规则。
- 资产买断或分期购买规则。
- 分期未结清前的权属保留规则。
- 尾款结清后的权属变更规则。
- 资产损坏、丢失、违约处理规则。
- 跨门店归还规则。

电子合同原则上不写死具体车架号、电池号或资产编号。租赁场景的具体资产在取车时通过资产交接单确认；如后续发生换车、换电池，以资产变更记录作为履约凭证。售卖场景的具体交付资产可通过资产交付单确认，并在权属变更记录中留痕。

资产凭证规则：

- 取车时生成资产交接单，记录实际交付的车架号、电池号或两者。
- 资产交接单需要用户确认，可采用电子确认、短信确认、手写签名或门店操作留痕。
- 更换资产时生成资产变更单，记录原资产、新资产、更换原因、操作人、门店和时间。
- 还车时生成资产归还单，记录实际归还资产、资产状态、损坏情况和补缴费用。
- 合同与资产交接单、变更单、归还单共同组成完整履约证据链。

支付宝能力说明：

- 支付宝支持身份认证相关开放能力；身份证正反面 OCR 可根据实际开通能力选择支付宝生态能力或第三方 OCR 服务。
- 支付宝支持周期扣款/商家扣款签约，可用于自定义期数账单的后续自动扣款。
- 支付宝支持芝麻免押，可用于押金减免或信用授权场景。
- 电子合同签署通常需要接入电子签服务商，或选择支付宝生态内可用的电子签能力，最终以开放平台资质和服务商能力为准。

支付方式：

自动扣款要求：

- 第一版本仅支持支付宝周期扣款或商家扣款协议。
- 所有租赁订单都需要在取车前确认逾期扣费方式，包括支付宝扣款协议、芝麻免押、资金授权、押金或主动补缴兜底。
- 用户首次下单时完成扣款协议签约。
- 签约完成后，系统保存协议号。
- 到达账单日时，服务端按协议号主动调用支付宝扣款接口。

- 用户取消协议、协议失效或扣款失败时，订单进入待补缴或异常状态。
- 微信自动扣款、微信支付和微信账单支付不进入第一版本范围。

- 订单创建。

- 电子合同签署。
- 自动扣款协议签约。
- 用户协议勾选。
- 资产绑定。

取车后订单进入“租赁中”。

### 5.7 还车

还车流程：

1. 用户到达取车门店或可归还门店。
2. 门店员工确认车辆/电池状态。
3. 系统核对资产编号。
4. 如有逾期、损坏、跨店费用，生成应付费用。
5. 用户支付补缴费用。
6. 订单完成。
7. 如有免押授权，按规则解除授权。

归还资产要求：

- 门店必须选择或扫码确认归还的车架号、电池号。
- 系统校验归还资产是否与订单绑定资产一致。
- 若发生资产更换，需要先完成资产更换记录，再结束订单。
- 订单完成后，资产状态恢复为空闲或进入待检修。

未按时归还处理：

- 超过预计还车时间后，系统自动生成续租账单。
- 若用户已签约自动扣款，系统自动扣款并顺延还车时间。
- 若扣款失败，用户端展示待补缴，后台展示逾期异常。
- 多次扣款失败后，可触发人工催收、限制再次租赁或违约处理。
