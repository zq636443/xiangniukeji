# 电车租赁平台开发实施计划

## 1. 开发原则

本计划不是 MVP 分期计划，而是工程开发顺序。目标是让团队按模块依赖逐步开发，先把底层业务骨架做稳，再做页面和三方能力，避免只实现表层页面导致订单、资产、账单、分润逻辑混乱。

核心原则：

- 先数据模型，再业务状态机，再页面。
- 先内部闭环，再接第三方。
- 先订单、账单、资产、分润这些核心领域，再做展示优化。
- 所有金额、规则、分润、出资方收益必须保存快照。
- 支付、扣款、核销、电子签全部通过服务端，不允许小程序直接调第三方敏感接口。
- 每个模块完成后必须有接口文档、测试用例和最小可操作页面。

## 2. 模块开发顺序总览

推荐顺序：

1. 工程基础与环境。
2. 账号、角色、权限。
3. 商户、门店、员工。
4. 出资方与资产基础台账。
5. 商品、SKU、门店 SKU、套餐。
6. 分润规则与规则快照。
7. 订单状态机。
8. 账单模型与账单生成。
9. 支付宝支付基础能力。
10. 支付宝签约与扣款任务。
11. 逾期订单汇总。
12. 资产交接、绑定、更换、归还。
13. 支付宝用户版小程序核心链路。
14. 支付宝商户版小程序核心链路。
15. 总部后台业务管理。
16. 芝麻免押/资金授权。
17. OCR、实名、电子合同。
18. 抖音/美团核销。
19. 分润结算与出资方收益。
20. 对账、导出、审计、上线加固。

## 3. 模块 1：工程基础与环境

目标：先把项目骨架、开发规范、部署环境打通。

后端：

- 创建 Spring Boot 后端工程。
- 建立模块目录：auth、merchant、product、order、bill、pay、asset、investor、settlement、verify、contract、job、common。
- 配置 MySQL、Redis、对象存储。
- 统一异常、统一返回、参数校验、日志格式。
- 集成 OpenAPI 文档。
- 建立数据库迁移机制。

前端：

- 创建独立的 `user-mini` 支付宝用户版小程序工程。
- 创建独立的 `merchant-mini` 支付宝商户版小程序工程。
- 创建独立的 `admin-web` React 后台工程，并在同一工程中支持总部模式与商户模式双工作台。
- 三个前端项目各自维护依赖、锁文件和构建命令。
- 配置环境变量：dev、test、staging、prod。

验收：

- 三个前端应用能启动。
- 后端健康检查接口可访问。
- 数据库迁移可执行。
- API 文档能自动生成。

## 4. 模块 2：账号、角色、权限

目标：先建立所有端的数据隔离和权限基础。

后端：

- 用户账号体系。
- 支付宝用户身份字段。
- 总部管理员账号。
- 商户老板、门店员工账号。
- 出资方账号。
- RBAC 角色权限。
- 门店级权限范围。
- 登录态、Token、刷新机制。

前端：

- 用户版小程序支付宝登录。
- 商户版小程序登录。
- 后台登录页。
- 后台权限菜单。

验收：

- 总部管理员能登录后台。
- 商户账号只能看到授权门店。
- 门店员工只能操作所属门店。
- 出资方只能看名下资产和收益。

## 5. 模块 3：商户、门店、员工

目标：建立业务组织结构，后续所有商品、订单、资产都挂在商户和门店下。

后端：

- 商户 CRUD。
- 门店 CRUD。
- 门店地址、营业时间、经纬度。
- 商户员工管理。
- 门店二维码生成。
- 门店启用/停用。

后台：

- 商户列表、创建、编辑。
- 门店列表、创建、编辑。
- 员工账号管理。
- 门店二维码下载。

商户版：

- 登录后选择门店。
- 查看当前门店基础信息。

验收：

- 总部可创建商户和门店。
- 每个门店能生成独立二维码。
- 商户端登录后只能看到授权门店。

## 6. 模块 4：出资方与资产基础台账

目标：先建立资产归属，不然后续订单收益和报废残值无法结算。

后端：

- 出资方管理。
- 车辆/车架资产台账。
- 电池资产台账。
- 资产绑定出资方。
- 资产当前所在门店。
- 资产状态：空闲、租赁中、待检修、维修中、已报废、已售出、异常。
- 资产归属历史。
- 维保费、残值字段。

后台：

- 出资方列表。
- 资产列表。
- 资产入库。
- 资产绑定出资方。
- 资产调拨门店。

商户版：

- 查看门店资产库存。
- 扫码查询资产。

验收：

- 车辆和电池可分别绑定出资方。
- 资产可调拨到门店。
- 资产状态变更有日志。
- 出资方可查看名下资产。

## 7. 模块 5：商品、SKU、门店 SKU、套餐

目标：建立“总部商品模板 + 门店商品链接”体系。

后端：

- 全局 SKU。
- 商品分类。
- 套餐。
- 门店 SKU。
- 门店 SKU 价格、办单费、签单费承担方。
- 自定义租期、总期数、每期金额、账单日规则。
- 是否需要资产绑定。
- 是否支持跨店归还。
- 批量上架门店商品。

后台：

- SKU 管理。
- 套餐管理。
- 门店 SKU 配置。
- 批量上架。

用户版：

- 扫门店码后展示门店商品列表。
- 商品详情和套餐选择。

验收：

- 同一个 SKU 在不同门店能配置不同价格和分润。
- 门店未上架的 SKU 不在用户端展示。
- 后台可批量上架多个门店。

## 8. 模块 6：分润规则与规则快照

目标：先把财务规则做成可计算、可追溯，避免订单完成后算不清账。

后端：

- 平台默认分润规则。
- SKU 默认分润规则。
- 门店默认分润规则。
- 门店 SKU 独立分润规则。
- 门店办单费。
- 门店租金分成。
- 出资方收益比例。
- 出资方运营手续费。
- 资产类型维保费。
- 规则生效时间和失效时间。
- 下单时生成规则快照。

后台：

- 分润规则配置。
- 规则预览。
- 规则启用/停用。

验收：

- 系统能按优先级命中分润规则。
- 下单时能保存价格和分润规则快照。
- 修改规则不影响历史订单。

## 9. 模块 7：订单状态机

目标：先把订单状态流转做严谨，前端页面只围绕状态机操作。

后端：

- 订单主表。
- 订单明细。
- 订单状态机。
- 操作日志。
- 状态变更校验。
- 取消订单。
- 异常订单标记。

核心状态：

- 待支付。
- 待实名。
- 待签约。
- 待免押。
- 待核销。
- 待取车。
- 租赁中。
- 待还车。
- 已逾期。
- 待补缴。
- 已完成。
- 已取消。
- 异常。

后台：

- 订单列表。
- 订单详情。
- 状态流转日志。

验收：

- 非法状态不能跳转。
- 每次状态变更都有操作日志。
- 用户端、商户端、后台看到的订单状态一致。

## 10. 模块 8：账单模型与账单生成

目标：订单不能只记录总金额，必须拆账单，否则扣款、逾期、分润都做不稳。

后端：

- 首期账单。
- 分期账单。
- 续租账单。
- 逾期账单。
- 补缴账单。
- 账单状态机。
- 自定义期数账单生成。
- 每期金额、账单日、到期时间。
- 账单和订单关联。

后台：

- 账单列表。
- 账单详情。
- 手动关闭账单。
- 手动标记异常。

验收：

- 任意自定义租期可生成账单计划。
- 账单金额合计和订单金额一致。
- 账单状态变更有日志。

## 11. 模块 9：支付宝支付基础能力

目标：先打通主动支付，所有扣款和补缴都依赖支付基础设施。

后端：

- 支付单。
- 支付宝交易创建。
- 支付回调验签。
- 支付幂等处理。
- 退款接口。
- 支付状态查询。
- 支付单和账单关联。

用户版：

- 首期支付。
- 签单费支付。
- 押金或补缴支付。

后台：

- 支付单查询。
- 支付回调记录。

验收：

- 支付成功能正确更新支付单、账单、订单。
- 重复回调不会重复入账。
- 支付失败不会改变订单关键状态。

## 12. 模块 10：支付宝签约与扣款任务

目标：实现后续账单扣款，不把“签约”和“扣款”混为一谈。

后端：

- 发起支付宝签约。
- 保存协议号。
- 签约状态查询。
- 解约处理。
- 扣款任务。
- 扣款重试。
- 扣款幂等锁。
- 扣款失败原因记录。

任务：

- 每日扫描到期账单。
- 生成扣款批次。
- 调用支付宝扣款。
- 更新账单状态。
- 失败进入逾期处理。

用户版：

- 下单时签约。
- 查看签约状态。

验收：

- 签约成功后能保存协议号。
- 账单日能由服务端主动扣款。
- 重复任务不会重复扣款。
- 扣款失败能记录原因。

## 13. 模块 11：逾期订单汇总

目标：扣款失败不能散落在账单里，要形成运营可处理的逾期台账。

后端：

- 逾期订单汇总表。
- 扣款失败生成逾期记录。
- 按月归集。
- 逾期金额、未补缴金额、失败次数。
- 催缴状态。
- 催缴备注。

后台：

- 逾期订单汇总列表。
- 按商户、门店、用户、商品筛选。
- 导出逾期明细。

商户版：

- 查看门店逾期订单。
- 发起补缴提醒。
- 添加催缴备注。

验收：

- 扣款失败后自动出现在逾期汇总。
- 补缴成功后逾期记录状态同步更新。
- 后台和商户版逾期数据一致。

- 资产交接单。

- 资产归还单。
- 资产状态变更。
- 资产操作日志。
- 车架/电池分别绑定。
- 换车/换电池。

商户版：

- 更换资产。
- 还车确认。
- 结束订单。

后台：

- 查看资产履约凭证。
- 查看资产操作记录。

验收：

- 还车后资产回到空闲或待检修。

## 23. 禁止事项

开发过程中禁止：

- 先做页面，后补订单状态机。
- 订单只存总金额，不拆账单。
- 分润只在页面临时计算，不保存快照。
- 资产更换只改订单字段，不生成资产变更单。
- 支付回调不做幂等。
- 扣款任务多实例并发重复扣。
- 小程序直接调用支付宝、抖音、美团敏感接口。
- 商户端绕过权限查看其他门店数据。
- 合同写死车架号/电池号。

## 24. 每个模块交付标准

每个模块完成时必须包含：

- 数据表迁移脚本。
- 后端接口。
- 接口文档。
- 权限校验。
- 操作日志。
- 基础测试用例。
- 后台最小管理页面。
- 小程序必要页面或占位入口。
- 异常场景说明。

只有满足这些条件，才允许进入下一个强依赖模块。
