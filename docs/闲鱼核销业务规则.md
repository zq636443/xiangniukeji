# 闲鱼核销业务规则

## 1. 目标

闲鱼场景不是平台内直接下单，而是用户先在闲鱼成交，再到线下门店履约。

本规则用于明确以下问题：

- 闲鱼订单如何进入享牛平台履约链路。
- 用户、门店、总部分别做什么。
- 平台收什么钱，不收什么钱。
- 核销码如何下发、校验、使用和作废。
- 闲鱼核销如何与实名、签约、押金授权、取还车、逾期扣款、分润结算打通。

## 2. 适用范围

本规则适用于：

- 用户已在闲鱼完成商品主货款支付。
- 用户到线下合作门店提车或租电池。
- 平台仅收取签单费，并由平台承接后续租赁履约。

本规则不适用于：

- 平台内普通线下直租。
- 抖音、美团团购券自动核销。
- 平台内资产售卖或买断订单。

## 3. 角色分工

### 3.1 总部 / 闲鱼运营部

- 根据闲鱼成交结果，在总部后台下发闲鱼核销码。
- 指定核销码对应的门店商品、套餐、核销金额。
- 处理异常码、作废码、重复码。
- 跟踪闲鱼来源订单的核销、签单费支付和履约情况。

### 3.2 商户 / 门店

- 线下接待用户。
- 出示门店二维码，引导用户进入用户版小程序。
- 协助用户选择`核销来源 = 闲鱼`并录入核销码。
- 在商户端查看核销状态、处理异常、完成取还车与资产更换。

### 3.3 用户

- 在闲鱼完成下单。
- 到店后出示闲鱼核销码。
- 进入用户版小程序，完成验码、签单费支付、实名、签约、押金授权。
- 后续按平台租赁规则使用、归还、续租和处理逾期。

## 4. 业务定义

### 4.1 闲鱼核销码

闲鱼核销码是享牛平台内部认可的履约凭证，不等同于支付宝支付码，也不依赖闲鱼开放平台自动核销接口。

V1 规则：

- 核销码由总部后台下发。
- 每个核销码只允许成功使用一次。
- 每个核销码必须绑定一个明确的门店商品和套餐。
- 用户到店后必须选择与核销码一致的商品与套餐，不能随意改绑。

### 4.2 收费口径

闲鱼场景下：

- 商品主货款：用户已在闲鱼支付，平台内不再重复收取。
- 平台内收费：只收签单费。
- 后续履约：实名、签约、押金授权、取车、归还、逾期代扣等仍走平台租赁链路。

### 4.3 订单属性

闲鱼核销成功后，平台会创建一笔内部租赁订单，作为履约订单存在。

该订单具备以下特征：

- `sourcePlatform = XIANYU`
- `voucherCode` 记录闲鱼核销码
- `voucherAmount` 记录闲鱼已成交金额
- `signFeeAmount` 记录平台内应收签单费
- 平台订单首期不再收租金，只收签单费

## 5. 标准链路

### 5.1 总部下发核销码

总部或闲鱼运营人员在后台创建闲鱼核销码时，需要填写：

- 核销码
- 对应门店商品
- 对应套餐
- 闲鱼成交金额
- 核销标题或备注

系统自动带出：

- 商户
- 门店
- 签单费

下发完成后，核销码进入`INPUT`状态，表示已建码、待用户到店使用。

### 5.2 用户到店验码

1. 用户到线下门店。
2. 门店出示门店二维码。
3. 用户扫码进入用户版小程序。
4. 用户选择与闲鱼订单一致的商品和套餐。
5. 用户选择核销来源平台为`闲鱼`。
6. 用户输入或扫码录入闲鱼核销码。
7. 系统校验该核销码是否已由总部下发、是否未被他人使用、是否与当前商品套餐一致。

校验通过后，核销记录进入`PREPARED / VERIFIED`链路。

### 5.3 生成签单费订单

验码成功后，系统创建：

- 一笔平台内部租赁订单
- 一笔签单费账单

此时：

- 用户需先支付签单费
- 未支付签单费前，核销记录不能进入最终核销成功状态

### 5.4 支付签单费并完成核销

1. 用户支付签单费。
2. 系统确认账单已支付。
3. 系统将闲鱼核销记录置为`CONSUMED`。
4. 系统将订单状态流转到`待实名`。

说明：

- 闲鱼 V1 不依赖外部自动核销接口。
- `CONSUMED` 表示平台内部已完成核销闭环，并锁定该核销码不可再次使用。

### 5.5 后续履约

核销成功后，后续流程与普通租赁一致：

- 实名
- 电子签约
- 押金或资金授权
- 取车
- 换资产
- 归还
- 逾期自动扣款

## 6. 校验规则

### 6.1 核销码唯一性

- 同一平台下，核销码唯一。
- 同一个闲鱼核销码不可重复成功使用。

### 6.2 商品套餐匹配

闲鱼核销码必须和下发时绑定的门店商品、套餐一致：

- 商品不一致，不允许验码。
- 套餐不一致，不允许验码。
- 门店不一致，不允许验码。

### 6.3 使用人锁定

当某个用户首次完成验码准备后：

- 核销记录会锁定当前用户。
- 其他用户不能再继续操作同一个核销码。

### 6.4 状态限制

- `CONSUMED`：不可再次使用。
- `CONSUMING`：不可重复提交。
- `EXCEPTION`：需总部人工处理。

## 7. 状态机

| 状态 | 含义 |
| --- | --- |
| `INPUT` | 总部已下发核销码，待用户到店使用 |
| `PREPARED` | 已完成验码准备 |
| `VERIFIED` | 已确认验码，可生成签单费订单 |
| `WAITING_SIGN_FEE` | 已生成签单费账单，待支付 |
| `CONSUMING` | 正在提交核销完成动作 |
| `CONSUMED` | 核销完成，不可再次使用 |
| `FAILED` | 本次校验或核销失败，可按规则重试 |
| `EXCEPTION` | 人工标记异常，需总部处理 |

## 8. 结算口径

闲鱼来源订单的结算遵循以下原则：

- 平台内实收只统计签单费。
- 闲鱼主货款不直接进入平台支付流水。
- 如需后续把闲鱼主货款纳入平台分润台账，必须新增“外部实收映射”和“外部实收对账”能力后再启用。

V1 默认口径：

- 门店办单费可以照常按平台规则计算。
- 平台实际到账只看签单费。
- 闲鱼主货款先不纳入平台内租金分润实收确认。

## 9. 异常场景

### 9.1 核销码不存在

- 提示：核销码不存在或未下发。
- 不创建订单。

### 9.2 核销码与商品套餐不一致

- 提示：核销码与当前选择的商品或套餐不匹配。
- 不创建订单。

### 9.3 核销码已被使用

- 提示：该核销码已完成核销，不能重复使用。
- 不允许继续支付和履约。

### 9.4 签单费未支付

- 不允许进入最终核销完成状态。
- 不允许订单进入实名后续链路。

### 9.5 门店现场异常

商户或总部可将记录标记为`EXCEPTION`，并填写异常原因，例如：

- 用户订单信息与核销码不符
- 用户拒绝支付签单费
- 线下已处理但系统未完成

## 10. 数据沉淀要求

闲鱼核销记录至少需要保存：

- 来源平台
- 核销码
- 用户
- 商户
- 门店
- 门店商品
- 套餐
- 订单
- 签单费账单
- 核销金额
- 签单费金额
- 核销状态
- 异常原因
- 失败原因
- 验码时间
- 核销完成时间

## 11. V1 落地边界

V1 明确采用以下落地方式：

- 闲鱼核销码由总部后台手工下发。
- 平台内部完成码校验和状态流转。
- 不依赖闲鱼官方自动核销接口。
- 商户端负责协助，用户端负责支付与后续签约履约。

后续如接入闲鱼开放平台或第三方服务商接口，再扩展：

- 订单同步
- 实收回传
- 自动核销确认
- 外部对账
